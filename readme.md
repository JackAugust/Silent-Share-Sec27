# Silent-Share: Privacy-Preserving Bilateral Threshold Matching for Web Access Control

This repository contains the implementation and benchmarking framework for the **Silent‑Share** protocol described in the paper *"Silent‑Share: Privacy-Preserving Bilateral Threshold Matching for Web Access Control"*.

The code enables full reproduction of the experimental results, including:
- Dense Vandermonde GOKVS baseline
- G2 exponentiation profiling motivating the sparse redesign
- Sparse GOKVS parameter selection
- One‑sided and bilateral Silent‑Share benchmarks
- **Fair comparison with Fuzzy IB-ME** (used in the paper's main evaluation)

All experiments are conducted on the BN254 asymmetric pairing curve.

## Environment and Dependencies

The experiments were run in the following environment:

- **OS**: Ubuntu 20.04.1 LTS
- **Python**: 3.6.13 (via Conda)
- **Charm-Crypto**: 0.50
- **PBC**: 0.5.14
- **OpenSSL**: 1.1.1n
- **GMP**: 6.2.1
- **Additional Python packages**: `psutil`, `pandas`, `matplotlib`

The Charm-Crypto library must be installed with support for the **BN254** asymmetric pairing curve. The current code sets `CURVE = 'BN254'` in `config.py`.

## Fair Comparison Experiments (Paper Results)

The performance figures in the paper's main evaluation are generated by the redesigned fair benchmark scripts located in `src/benchmarks/baseline/`. These scripts run both Silent‑Share and Fuzzy IB-ME under **identical parameter settings**, using the same BN254 curve, the same number of repeats, and the same measurement conventions. The key property is that **only the cryptographic operations of interest are timed**, and both schemes are evaluated using the "hint" mode (i.e., the correct \(d\)-subset is provided). This isolates the true per‑candidate reconstruction cost and avoids unfairly penalizing Fuzzy IB-ME for its subset‑search overhead, which is analyzed separately.

### Running the Fair Benchmarks

```bash
# Fuzzy IB-ME baseline (BN254)
python src/benchmarks/baseline/fuzzy_ibme_baseline.py \
    --rounds 5 --warmup 1 --d 5 \
    --policy-sizes 10,25,50,100,200,400 \
    --attr-sizes 5,10,15,20,25,30 \
    --d-list 2,3,4,5,6,7,8,9,10 \
    --overlap-list 5,10,15,20,25,30

# Silent-Share (matching parameters)
python src/benchmarks/baseline/silent_share_VS_Fuzzy_IBME.py \
    --rounds 5 --warmup 1 --d 5 \
    --policy-sizes 10,25,50,100,200,400,800 \
    --attr-sizes 5,10,15,20,25,30 \
    --d-list 2,3,4,5,6,7,8,9,10 \
    --overlap-list 5,10,15,20,25,30
```

These commands generate CSV files in the respective output directories (by default `fuzzy_ibme_bn254_fair_results/` and `silent_share_results/`). The files contain mean and standard deviation for each metric.

### Generating the Fair Comparison Figures

```bash
python src/plot_comparison.py
```

This script reads the redesigned CSV outputs from both schemes and generates the six PDF figures used in the paper:

- `enc_time_vs_policy.pdf`
- `ct_size_vs_policy.pdf`
- `dec_time_vs_attr.pdf`
- `dk_size_vs_attr.pdf`
- `dec_time_vs_threshold.pdf`
- `search_space_comparison.pdf`

It also outputs a combined CSV `data_csv/combined_redesign.csv` for further analysis.

> **Important:** The older `fuzzy_aligned_bench.py` and `one_sided_bench.py` scripts are kept for archival and additional microbenchmarks, but their outputs are **not** used in the paper's main fair comparison. They do not enforce identical parameter conventions and may produce inconsistent results. Please refer to the `baseline/` scripts for reproducible fair comparison data.

## Configuration Notes

All benchmark parameters are centralized in `src/config.py`:

- `CURVE`: pairing curve (`'BN254'`)
- `USE_SPARSE_GOKVS`: set to `True` to use sparse GOKVS
- `SPARSE_GOKVS_RHO`: row sparsity (`3`)
- `SPARSE_GOKVS_M_FACTOR`: bucket ratio \(m/n\) (`1.25`)
- `POLICY_SIZES`, `ATTR_SIZES`, `ROUNDS`: parameter ranges for standard benchmarks

The fair comparison scripts accept command‑line arguments and do **not** rely on `config.py` for their parameter lists. This allows precise alignment of both schemes.

## Reproducibility

Every benchmark script writes one row per repetition to CSV. The terminal output prints mean and standard deviation. For the fair comparison, the `baseline/` scripts generate CSV files with `*_mean` and `*_std` columns, and `plot_comparison.py` consumes them to produce publication‑ready figures.

We encourage reviewers to run the fair comparison scripts first, as these directly correspond to the paper's main experimental claims. The remaining standard benchmarks provide supplementary evidence about GOKVS behavior and protocol scalability.
